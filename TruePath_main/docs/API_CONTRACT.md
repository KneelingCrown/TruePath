# Контракт Android-фронтенда True Path

## Область

Собственный сервер не создаём. Android-клиент обращается к выбранным внешним API напрямую. Текущий учебный источник не делает сетевых запросов; реальные адреса и методы поставщика не выдумываются.

## Интерфейс потока

```kotlin
interface ResearchSource {
    fun events(session: ResearchSession): Flow<ResearchEvent>
}
```

Адаптер сопоставляет реальные сообщения поставщика с доменными событиями:

| Событие | Поведение клиента |
| --- | --- |
| `Stage` | Показать текущий этап без выдуманного процента готовности |
| `UpsertNode` | Добавить или изменить узел с постоянным ID |
| `UpsertEdge` | Добавить или изменить связь; дождаться обоих узлов |
| `Finished` | Зафиксировать итог после подтверждения завершения |
| `Failed` | Сохранить частичный граф и показать ошибку |
| `NeedsApi` | Локальный статус прототипа: материал сохранён, проверка не проводилась |

Каждое событие имеет стабильный уникальный ID. Повторные доставки безопасны. Изменение уже существующего узла приходит с новым ID события и прежним ID узла.

## Доказательства

Для каждого утверждения нужны проверяемый текст, статус и объяснение. Для доказательства — цитата или конкретный фрагмент, источник, URL либо ссылка на сохранённый материал. Отсутствие подтверждения не означает опровержение. Совпадение цитаты с текстом не устанавливает истинность всех выводов.

В текущем прототипе координаты узлов приходят из учебного сценария. При интеграции реальных данных клиент должен назначать устойчивые координаты новым узлам, сохраняя существующий layout и камеру. Не требуется, чтобы поставщик API рассчитывал координаты визуализации.

## Проверка возможностей поставщика

- Структурированные промежуточные источники и доказательства доступны до завершения задачи.
- Известно, что означает завершение и как сообщаются ошибки.
- Можно получить состояние запущенной задачи по её ID после перезапуска приложения.
- Известен механизм восстановления: курсор событий или актуальный снимок.
- Понятны ограничения текста, изображений, документов и видео. При необходимости распознавание вынесено в отдельный API.
- Проверены доступность сервиса, расходы и качество русскоязычных материалов.

SSE, NDJSON либо частичные структурированные снимки подходят при выполнении этих требований. Поток токенов финального отчёта сам по себе не обеспечивает живой граф доказательств. Нельзя выдавать локальную анимацию заранее готового отчёта за потоковое исследование.

## Ключи и файлы

Не включать общие платные ключи в исходники или APK. Для версии без своего сервера нужен пользовательский ключ либо поддерживаемая поставщиком клиентская авторизация. Выбранные через системный диалог URI не являются публичными URL: при реальной загрузке нужно читать поток через `ContentResolver`, проверять размер и поддерживаемый формат, показывать назначение передачи.

Удаление локальной истории сейчас удаляет запись и ссылки на выбранные файлы. Файлы пользователя вне приложения не удаляются. При появлении внешнего API удаление локальной записи не должно обещать удаление копий у поставщика без подтверждённого API удаления.

## Реализация поставщика: True Path backend

Для учебного этапа роль поставщика выполняет собственный сервис `backend/` (FastAPI): он удовлетворяет требованиям из разделов выше — запуск задачи по ID, структурированные промежуточные события, восстановление задачи, явные ошибки. Клиент обращается к нему через `BackendResearchSource`, реализующий тот же интерфейс `ResearchSource`, что и демо-поток; демо-сценарии ленты остаются на `DemoResearchSource`.

### Операции

| Операция | Метод | Поведение |
| --- | --- | --- |
| Сохранить материал | `POST /api/v1/materials` | Текст или ссылка; возвращает `material_id` |
| Создать исследование | `POST /api/v1/research` | `{material_id, client_task_id?}`; повтор с тем же `client_task_id` возвращает существующую задачу (идемпотентность, 200 вместо 201) |
| Наблюдать исследование | `GET /api/v1/research/{id}/events?after=N` | События с курсором `seq > N`; транспорт — частичные снимки-списки |
| Восстановить исследование | тот же запрос с `after=0` и прежним `client_task_id` | Полный список событий заново; повторная доставка отсекается редуктором по id события |
| Итог и граф | `GET /api/v1/research/{id}/result`, `.../graph` | Снимок результата и графа с объяснениями связей |
| Обновить исследование | `POST /api/v1/research/{id}/refresh` | Создаёт отдельную запись; прежний результат сохраняется |

### События

Список событий детерминированный: он вычисляется из состояния задачи, поэтому повторный запрос с тем же курсором возвращает те же события. Идентификаторы стабильные (`stage-1`, `node-7`, `edge-3`, `claim-status-7`, `finished-1`, `failed-1`); изменение узла приходит как новое событие с прежним `ref` узла.

| Событие сервера | Доменное событие клиента |
| --- | --- |
| `stage` (`text`) | `Stage` |
| `upsert_node` (`node`: ref, kind, label, status, description, quote, source_label, source_url) | `UpsertNode` |
| `upsert_edge` (`edge`: ref, from_ref, to_ref, label, explanation, is_established) | `UpsertEdge` |
| `finished` (`summary`, `plan_b`) | `Finished` |
| `failed` (`message`) | `Failed` |

Координаты узлов сервер не рассчитывает — их назначает клиент (адаптер раскладывает узлы детерминированно по типу). Узел материала сервера отображается адаптером на локальный узел `material`, который ViewModel создаёт при запуске.

### Соответствие статусов

| Статус сервера | `TrustStatus` клиента |
| --- | --- |
| `supported` | `SUPPORTED` |
| `insufficient` | `UNCERTAIN` |
| `refuted` | `CONTRADICTED` |
| `out_of_scope` | `UNCHECKED` |

Отсутствие подтверждения на сервере — `insufficient`, а не `refuted`; ошибка этапа — `failed` с человекочитаемой причиной и не превращается в результат.

### Известные ограничения интеграции

- `plan_b` в событии `finished` заполнен шаблонными карточками «План Б» (детерминированные заглушки по ТЗ); связывание пользовательских задач с утверждениями — через `POST/GET /api/v1/plans`.
- Файлы и изображения клиентом на сервер не передаются: собственный текст проверяется через backend, вложения сохраняются локально с непроверенным статусом (OCR — явная заглушка).
- Cleartext-трафик разрешён только к адресу эмуляторного сервера `10.0.2.2` (`res/xml/network_security_config.xml`); общий cleartext запрещён. Для проверки с реального устройства добавьте адрес машины в конфиг или поднимите HTTPS.
- Лента на сервере работает на фикстурных публикациях (по ТЗ внешних API нет); клиентский фид пока читает локальные фикстуры — переход на серверную ленту не обязателен для MVP.
