# True Path — концепция и план Android-приложения

> Область нашей работы: фронтенд и Android-приложение — экраны, навигация, умная лента, загрузка материалов, визуализация графов, история и подключение внешних API. Собственную серверную часть не разрабатываем.

## Статус концепции и команда

Концепция зафиксирована 25 октября 2026 года как основа для следующего этапа — подготовки ТЗ команды. Документ описывает целевой продукт; текущее состояние реализации и ограничения демонстрации перечислены в [README](../README.md).

В команде три участника:

- **DevOps/Pipeline — автор проекта совместно с Codex:** среда разработки, воспроизводимые проверки и pipeline.
- **Front:** Android-интерфейс, экраны, навигация и визуализация.
- **Back:** интеграции внешних API и обработка их данных в рамках Android-приложения. Название роли не вводит собственную серверную часть.

Границы ответственности, задачи, контракты между Front и Back, критерии приёмки и порядок интеграции определены в [рабочем ТЗ MVP](TECHNICAL_SPEC.md).

Базовый пользовательский сценарий: явный запуск проверки → этапы исследования → результат и граф доказательств → сохранение в истории. По завершении проверки открывается визуализация; повторное открытие истории показывает сохранённый граф без нового платного исследования. Описанный ниже потоковый граф уточняет отображение промежуточных результатов: он доступен во время проверки и сохраняет итог после её завершения.

## 1. Идея проекта

**True Path — Android-приложение, которое объединяет умную новостную ленту, глубокое исследование информации и интерактивный граф доказательств.**

Пользователь читает новости из выбранных источников или загружает собственные материалы: сообщения, ссылки, скриншоты, изображения, документы и видео. По его запросу ИИ выделяет проверяемые утверждения, ищет первоисточники, сопоставляет сведения и объясняет, какие выводы подтверждаются, какие опровергаются, а для каких информации недостаточно.

Граф строится в режиме стриминга прямо во время исследования: по мере поступления данных появляются утверждения, источники, доказательства и связи, обновляются статусы. Пользователь наблюдает ход проверки и может проследить путь от утверждения до конкретного доказательства. Исследования сохраняются и постепенно формируют личную базу знаний.

Дополнительная механика — связь информации с планами пользователя. Если важное решение зависит от спорного утверждения, приложение показывает эту зависимость и предлагает «План Б» — возможные действия в условиях неопределённости.

## 2. Какую проблему решаем

Человек получает информацию одновременно из новостных сайтов, каналов, переписок, изображений и видео. Ему трудно быстро понять:

- Откуда появилось утверждение?
- Подтверждают ли его несколько независимых источников или все пересказывают один материал?
- Совпадает ли заголовок с содержанием?
- Не потерялись ли дата, оговорка или область действия документа?
- Можно ли использовать эту информацию для собственного решения?
- Что делать, если окончательного ответа пока нет?

True Path сокращает путь от сомнения до обоснованного решения и сохраняет основания вывода для последующего возвращения к ним.

## 3. Основной пользовательский сценарий

1. Пользователь находит интересующую публикацию в ленте или отправляет собственный материал.
2. Запускает фактчекинг.
3. Приложение сразу открывает вкладку визуализации в режиме текущего исследования.
4. По мере поступления данных граф дополняется утверждениями, источниками, доказательствами и связями; статусы узлов обновляются.
5. Пользователь видит этап проверки, изучает уже полученные материалы и раскрывает основания связей, пока исследование продолжается.
6. После завершения в том же графе фиксируются итоговые статусы и краткий вывод.
7. Промежуточное состояние и итоговая проверка сохраняются в истории.

Один материал может содержать несколько утверждений с разными результатами проверки. Поэтому приложение оценивает их отдельно, сохраняя общий контекст публикации.

## 4. Структура приложения

### Лента

Лента содержит новости из выбранных источников. Пользователь выбирает интересующие темы и может изменять свои предпочтения.

Умная обработка ленты включает:

- объединение публикаций об одном событии;
- уменьшение числа повторов;
- краткое описание события;
- выделение новых подробностей;
- ранжирование с учётом выбранных тем, свежести и уже просмотренных материалов.

При первом запуске интересы задаются явно. Далее приложение может учитывать сохранения, скрытия и отметки «интересно / неинтересно», предоставляя пользователю возможность корректировать рекомендации.

**Фактчекинг новости запускается только по нажатию пользователя.** Сбор публикации, её краткое описание или попадание в рекомендации не означают, что она проверена.

Если событие уже исследовалось, карточка может содержать переход к сохранённой проверке с указанием её даты. Новые подробности не получают старый статус автоматически.

### Фактчекинг

Вкладка содержит чат для ввода и загрузки материалов:

- текстовых утверждений и сообщений;
- ссылок на публикации;
- скриншотов и изображений;
- документов;
- аудио и видео по мере подключения соответствующей обработки.

Пользователь может добавить контекст: «Проверь дату», «Соответствует ли заголовок документу?», «Можно ли на основании этого менять мои планы?».

Отправка материала на проверку запускает исследование. Если запрос неоднозначен, приложение предлагает уточнить предмет проверки.

Для изображений сначала извлекается текст и определяется, какие элементы требуют визуального анализа. Для видео и аудио используются расшифровка и, при необходимости, отдельные кадры. Полнота обработки отображается явно: анализ расшифровки не должен выдаваться за проверку подлинности видеозаписи.

### Визуализация

**Граф отображается в режиме стриминга с момента запуска проверки.** Здесь отображаются:

- текущий этап исследования и отметка о незавершённости проверки;
- поступающие промежуточные результаты, а после завершения — краткий итог;
- проверяемые утверждения;
- интерактивный граф, который дополняется и обновляется по мере поступления данных;
- источники и конкретные фрагменты материалов;
- подтверждения, противоречия и открытые вопросы;
- связанные планы пользователя, если они добавлены.

Нажатие на узел открывает подробности. Нажатие на связь объясняет, на каком основании она построена.

Переход на эту вкладку происходит сразу после запуска проверки. После завершения текущий граф переходит в итоговое состояние без повторного открытия экрана и сброса положения камеры. Если пользователь ушёл на другую вкладку, он может вернуться к текущей проверке. После повторного открытия приложения восстанавливается сохранённый граф и запрашивается актуальное состояние исследования.

### История

История хранит проведённые исследования, исходные материалы, даты и результаты.

Можно искать проверки по теме или тексту, повторно открывать материалы и запускать обновление исследования.

**Нажатие на запись открывает сохранённый граф во вкладке визуализации.** Для незавершённой проверки возобновляется получение доступных обновлений по её идентификатору. Повторное открытие не запускает новое платное исследование. Новая проверка или повторное исследование выполняется отдельным действием.

## 5. Как работает глубокая проверка

Исследование состоит из последовательных этапов:

1. **Разбор материала.** Извлечение текста, ссылок, дат, имён и проверяемых утверждений.
2. **Определение вопросов.** Что именно требуется установить и какие сведения могут это подтвердить.
3. **Поиск оснований.** Поиск первичных документов, полных записей, прямых заявлений и других относящихся к вопросу материалов.
4. **Сопоставление.** Проверка соответствия цитат источникам, дат, чисел, формулировок и области действия утверждения.
5. **Дополнительный поиск.** Уточнение обнаруженных противоречий и пробелов в пределах заданного бюджета.
6. **Формирование результата.** Выводы по отдельным утверждениям, граф доказательств и список оставшихся неизвестных.

На протяжении этих этапов приложение получает структурированные промежуточные данные и обновляет визуализацию. Первые узлы появляются до завершения полного исследования. Промежуточные выводы помечаются как предварительные и могут быть пересмотрены при поступлении новых доказательств.

Источники новостной ленты и область исследовательского поиска настраиваются отдельно. Проверка может обращаться к первичным материалам за пределами списка читаемых изданий.

Если оригинал недоступен или найден только пересказ, это отражается в результате.

## 6. Граф доказательств

Основные типы узлов:

- **Материал:** загруженная публикация, документ, изображение или видео.
- **Утверждение:** конкретное проверяемое высказывание.
- **Источник:** страница, документ, запись или другой материал, использованный в исследовании.
- **Доказательство:** цитата, фрагмент документа или кадр с привязкой к источнику.
- **Событие:** общая тема, объединяющая несколько публикаций.
- **План или задача:** действие пользователя, связанное с информацией.

Основные связи:

- материал содержит утверждение;
- доказательство подтверждает, опровергает или ограничивает утверждение;
- публикация ссылается на источник;
- материалы относятся к одному событию;
- задача зависит от утверждения.

Предполагаемые связи визуально отличаются от подтверждённых. Сходство текстов само по себе не доказывает, что одна публикация скопирована из другой.

Каждая содержательная связь должна иметь объяснение. Граф помогает исследовать основания вывода, поэтому наличие большого количества узлов не является самостоятельной целью.

### Потоковое построение графа

- Исходный материал появляется первым узлом сразу после запуска проверки.
- Утверждения, источники и доказательства добавляются по мере их получения от API.
- Связи появляются вместе с основаниями; если связанный узел ещё не получен, обновление ожидает его появления.
- Узлы и связи имеют постоянные идентификаторы. Повторное получение события обновляет существующий элемент и не создаёт дубликат.
- Изменение статуса обновляет существующий узел с понятной анимацией и сохраняет объяснение изменения.
- Новые данные применяются небольшими порциями без полной перерисовки графа. Масштаб, выбранный узел и положение камеры сохраняются. Предусмотрена кнопка «Показать весь граф».
- Пользователь может перемещать граф, открывать узлы и читать уже полученные доказательства во время исследования.
- При обрыве соединения полученная часть графа остаётся доступной с отметкой «Проверка не завершена». После восстановления соединения приложение получает пропущенные обновления или актуальный снимок, в зависимости от возможностей API.
- Событие завершения фиксирует итоговый результат. Ошибка или закрытие потока без подтверждения завершения не считаются успешным окончанием проверки.

## 7. Цвета и визуальный эффект

Статусы применяются прежде всего к отдельным утверждениям:

- **Зелёный:** найденные доказательства поддерживают утверждение в указанном контексте.
- **Жёлтый:** данных недостаточно, источники расходятся или остался существенный вопрос.
- **Красный:** найденные доказательства противоречат утверждению.
- **Серый:** утверждение ещё не проверено или не вошло в область исследования.

Статус сопровождается текстовым объяснением. Отсутствие подтверждения не превращает утверждение в опровергнутое.

Криптографическая подпись, история происхождения файла и личное свидетельство отображаются отдельными отметками с пояснением, что именно они устанавливают. Подлинный документ может быть неверно интерпретирован; настоящее изображение может сопровождаться неправильной подписью.

Пульсация используется во время исследования: пользователь видит реальное поступление источников, доказательств и связей, а также изменение статусов. Анимация сопровождает полученные данные; она не имитирует исследование с заранее готовым графом. После завершения граф становится спокойным и удобным для изучения. Цвет обязательно дублируется подписью или значком.

Приложение не обещает универсально определять любые дипфейки. Результаты специализированного анализа отображаются как отдельные сигналы с обозначением ограничений.

## 8. Связь со вторым мозгом и «План Б»

Каждая проверка сохраняет материал, выводы и основания. При следующем исследовании связанные события и утверждения могут использоваться повторно с учётом даты и актуальности.

Пользователь может связать утверждение со своей задачей:

> «Если мероприятие перенесено, нужно изменить время выезда».

Когда утверждение получает новый статус, приложение подсвечивает зависимую задачу и объясняет последствия.

«План Б» включает:

- что можно сделать при текущем уровне неопределённости;
- какие действия стоит отложить до уточнения;
- какое дополнительное свидетельство поможет выбрать вариант;
- какие альтернативы доступны пользователю.

Изменение статуса информации не отменяет и не переносит задачи автоматически. Приложение предлагает изменение, пользователь принимает решение.

Для первой версии достаточно простого механизма связи «утверждение → задача» и одной карточки альтернативных действий. Полноценный таск-менеджер можно развивать после проверки основного сценария.

## 9. Архитектура: Android и внешние API

**Собственная серверная часть не используется.**

Android-приложение напрямую обращается к внешним сервисам и отвечает за:

- получение новостей;
- интерфейс и рекомендации;
- загрузку материалов;
- запуск исследовательских задач;
- потоковое получение промежуточных данных и итогового результата;
- постепенное построение и обновление графа;
- локальное хранение истории.

Глубокое исследование выполняется у поставщика исследовательского API. Распознавание изображений, речи и обработка видео подключаются через подходящие API по необходимости.

Приложение сохраняет идентификатор запущенной задачи, промежуточный граф и доступный указатель продолжения потока, чтобы восстановить состояние после повторного открытия. Такая схема требует исследовательского API с поддержкой асинхронных задач и доступом к структурированным промежуточным результатам.

### Требования к API для стриминга графа

Обязательна возможность получать новые элементы и изменения графа до завершения исследования. Это может быть поток структурированных событий, например через SSE, либо доступные во время выполнения частичные снимки. Опрос только статуса «выполняется / завершено» этого требования не выполняет.

На стороне Android адаптер API приводит полученные данные к событиям интерфейса:

- изменение этапа исследования;
- добавление или обновление узла;
- добавление или обновление связи;
- пересмотр предварительного вывода с объяснением;
- завершение исследования;
- ошибка или прерывание.

Поток текстовых токенов отчёта сам по себе не является потоком графа. В визуализацию попадают только полностью полученные и проверенные по структуре элементы с идентификаторами и привязками к источникам. Частичный JSON и незавершённые текстовые фрагменты не отображаются как готовые доказательства.

При выборе поставщика нужно отдельно подтвердить поддержку промежуточных источников, доказательств и обновлений. API, который отдаёт только итоговый отчёт, не подходит для обязательного сценария живого графа без дополнительного исследовательского процесса. Возможности конкретного поставщика ещё предстоит проверить.

История, исходные материалы и графы хранятся локально. При отправке материала пользователь должен понимать, какие данные передаются внешнему сервису.

Для хакатона ключи вводятся через настройки. Общий платный ключ не встраивается в распространяемый APK. Доступность выбранного API, ограничения входных материалов, стоимость и качество русскоязычной проверки проверяются до окончательного выбора поставщика.

## 10. Объём первой работающей версии

Приоритетный законченный сценарий:

1. Лента из ограниченного набора выбранных источников.
2. Объединение повторяющихся публикаций и фильтрация по темам.
3. Проверка новости по кнопке.
4. Ввод собственного текста, ссылки или скриншота.
5. Исследование с сохранением идентификатора задачи.
6. Потоковое построение графа утверждений, источников и доказательств с момента запуска проверки.
7. История с повторным открытием визуализации.
8. Простой демонстрационный «План Б» для связанной задачи.

Обработка видео, сложная персонализация, автоматическое обновление сохранённых исследований и расширенное управление задачами относятся к следующим этапам.

## 11. Демо-сценарий

Используется явно обозначенный учебный сюжет с подготовленными материалами.

1. В ленте появляется публикация: «Начало мероприятия перенесено на воскресенье».
2. Пользователь запускает проверку и сразу попадает во вкладку визуализации с узлом исходной публикации.
3. По мере поступления результатов на графе появляются утверждения о дате и области действия объявления, затем найденные источники и связи. Непроверенные утверждения изначально серые; предварительные выводы явно помечены.
4. Исследование находит полный документ: перенос относится только к одному направлению программы. Соответствующие доказательства добавляются в граф в процессе работы.
5. Статус обобщённого утверждения обновляется: найденный документ ему противоречит. Пользователь видит изменение на графе и открывает соответствующий фрагмент. После завершения итог закрепляется в том же представлении.
6. Пользователь видит связанную задачу «Изменить время выезда».
7. «План Б» предлагает уточнить своё направление по расписанию перед изменением поездки.
8. Проверка сохраняется в истории; повторное открытие возвращает тот же граф.

Демонстрация показывает полный путь: публикация → исследование → объяснимый результат → решение пользователя.

## 12. Критерии готовности

- Новость из ленты проверяется только по явному действию пользователя.
- Загруженный материал сохраняется вместе с исследованием.
- Выводы связаны с конкретными источниками и фрагментами.
- Недостаток данных обозначается явно.
- Предположительные связи отличаются от установленных.
- Визуализация открывается сразу после запуска проверки; новые элементы появляются до её завершения.
- Граф обновляется по реальным промежуточным данным API.
- Промежуточные выводы помечены и могут пересматриваться с объяснением.
- Повторные события не создают дубликаты узлов и связей.
- Во время обновлений сохраняются масштаб, положение камеры и выбранный узел.
- После обрыва соединения сохраняется частичный граф с явной отметкой незавершённости.
- Ошибка API не отображается как результат проверки.
- История восстанавливает сохранённый граф без повторного исследования.
- Завершение проверки фиксирует итог в текущем графе без сброса визуализации.
- «План Б» объясняет свои основания и предлагает действия для подтверждения пользователем.

**Главная ценность True Path — дать человеку понятный путь от информационного сообщения к проверяемым основаниям и осознанному действию.**
