# True Path — журнал разработки

Журнал и подробные сообщения коммитов сохраняют контекст решений. По ним команда сможет описать пайплайн разработки для защиты проекта. Это описание фактически сделанного, а не обещание готовых интеграций. Автоматические проверки и порядок ревью команды описаны отдельно в [PIPELINE.md](PIPELINE.md).

## 01. Основа Android-приложения

**Дата:** 25 октября 2026. **Коммит:** `b555be6` — Create True Path Android frontend foundation.

**Задача.** Создать фронтенд в Android Studio без собственного бэкенда, сохранив возможность прямого подключения внешних API. APK не создавать.

**Реализация.** Kotlin и Jetpack Compose; четыре раздела: лента, проверка материалов, граф, история. Учебный поток событий добавляет узлы и связи, затем пересматривает статусы и завершает исследование. Чистый редуктор предотвращает дублирование событий и откладывает связи до появления узлов. История сохраняется локально в JSON; прерванное исследование можно продолжить. Собственные материалы получают непроверенный статус, поскольку реальный исследовательский API ещё не подключён.

**Проверки.** Компиляция Kotlin, 7 модульных тестов и Android Lint. Установочные артефакты не создавались.

## 02. Дизайн, полноэкранное исследование и медиа

**Дата:** 25 октября 2026. **Связанный коммит:** `feat(android): redesign research workspace and support rich news` — искать по заголовку в Git.

**Задача.** Заменить шаблонный интерфейс; оставить экран графа чистым; выделить исходную новость и финальный ответ; перенести материалы в меню справа сверху; поддержать медиа внутри публикаций.

**Решения и реализация.**

- Редакционная лента: тёплый светлый фон, графитовый текст, зелёный акцент, заголовки с засечками, обложка главной новости и компактные следующие публикации.
- Граф занимает отдельный экран. Нижняя навигация скрывается; возврат ведёт к разделу, из которого открыли исследование. Масштаб и положение камеры не сбрасываются при поступлении событий.
- Исходная новость выделена тёмной карточкой. После завершения появляется отдельный узел «Вывод», связанный с доказательствами, и кнопка чтения полного ответа. Для непроверенных или прерванных материалов вердикт не создаётся. Вывод для старых записей истории формируется из уже сохранённого результата без миграции данных.
- Правое меню содержит итог, материалы с цитатами и сведения об исследовании. Из него можно найти выбранный узел на графе, остановить или продолжить учебный поток.
- Статья представлена последовательностью блоков: абзац, фото, видео, ссылка. HTTPS-изображения загружаются через Coil; предусмотрены ошибка и повторная попытка. Учебные обложки имеют локальный резерв. Фото открываются на весь экран с масштабированием; видео — во внешнем проигрывателе или браузере.
- Сохранены явные обозначения учебных публикаций, иллюстраций и подготовленных результатов. Загрузка картинок не означает подключение реального фактчекинга.

**Ключевые файлы.** `GraphPresentation.kt`, `GraphBoard.kt`, `GraphScreen.kt`, `TruePathApp.kt`, `NewsContent.kt`, `ArticleMedia.kt`, `FeedScreen.kt`, `Theme.kt`. Источники медиа — в [ASSET_CREDITS.md](ASSET_CREDITS.md).

**Проверки.** Добавлены 6 модульных проверок: совместимость итогового узла с сохранённой историей, отсутствие вердикта до завершения, правила статуса и связей, ограничения URL и порядок медиаблоков. Вместе с исходными тестами — 13. В отдельном режиме Paparazzi рендерит ленту, чтение, ввод материала, полноэкранный граф, открытое меню ответа и историю без APK. Kotlin и Compose compiler обновлены синхронно до 2.1.21 для совместимости этого режима с SDK 36. Итог: компиляция и Android Lint прошли, 13 модульных тестов выполнены без ошибок; 6 экранных снимков записаны и визуально просмотрены. Сравнение финальных эталонов также прошло: 6 визуальных тестов без расхождений. Android Lint: 0 ошибок, 13 предупреждений о зависимостях и рекомендациях. Проверки на физическом устройстве не выполнялись.

**Ограничения.** Реальные новости, рекомендации, анализ вложений и исследовательские API пока не подключены. Видеоплеер внутри приложения отсутствует. Нажатие на связь графа пока не открывает объяснение. Проверка на физическом устройстве потребует отдельного разрешённого этапа сборки APK.

## Как продолжать журнал

Для каждого законченного этапа фиксировать задачу, принятое решение, затронутые части, выполненные проверки и оставшиеся ограничения. Сообщение коммита должно содержать:

1. Короткий заголовок изменения.
2. Что изменилось и зачем это нужно пользователю.
3. Чем проверено и какие ограничения остались.

Для итогового описания разработки: требования → модели и состояние → экраны и навигация → потоковый граф → хранение → медиа → проверка качества → следующие API-интеграции. Команда восстановления истории: `git log --reverse --format=fuller`.

## Пайплайн пользовательского сценария

Текущая демонстрация: учебная публикация → нажатие «Проверить» → локальный поток структурированных событий → обновление редуктора и сохранение истории → появление узлов и связей → пересмотр статусов → итоговый узел и полное объяснение в меню → повторное открытие из истории.

Будущий реальный сценарий заменит локальный учебный источник API-адаптером: материал → извлечение утверждений → поиск первоисточников → сопоставление оснований → структурированные промежуточные события → граф → итог с неопределённостями. Требования к этому этапу описаны в [API_CONTRACT.md](API_CONTRACT.md); в приложении он ещё не реализован.
