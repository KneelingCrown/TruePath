# True Path

Android-приложение с умной новостной лентой, проверкой пользовательских материалов и потоковым графом доказательств.

Документация команды: [концепция](docs/PROJECT.md), [ТЗ MVP и задачи DevOps/Pipeline, Front и Back](docs/TECHNICAL_SPEC.md), [контракт API](docs/API_CONTRACT.md).

Проверки изменений: [pipeline и порядок ревью](docs/PIPELINE.md).

## Текущее состояние

Это основа Android-фронтенда для хакатона. Работают четыре вкладки:

- **Лента:** три вымышленных учебных события, фильтрация по темам, обложки, чтение публикаций с фото, видео и ссылками, явный запуск демонстрационной проверки.
- **Проверить:** ввод текста и ссылок, вставка из буфера, выбор до пяти файлов через системный диалог и удаление вложений.
- **Граф:** полноэкранный потоковый граф, выделенные исходная новость и итог, масштабирование и перемещение; меню справа сверху открывает вывод, материалы и управление исследованием.
- **История:** локальные исследования, поиск, повторное открытие графа без повторного запуска и удаление записи.

Учебный поток идёт из `DemoResearchSource` и везде обозначен как демонстрация. **Реальный фактчекинг, сетевой сбор новостей, персональный алгоритм рекомендаций, распознавание файлов и внешние AI API пока не подключены.** Собственные материалы сохраняются с непроверенным статусом; приложение не придумывает для них источники или выводы. Содержимое выбранных файлов не анализируется и не отправляется в сеть.

Собственного бэкенда нет. Разрешение на интернет используется для HTTPS-иллюстраций новостей через Coil; учебные обложки также сохранены локально. Видео открывается во внешнем проигрывателе или браузере. API-ключей в проекте нет.

## Открытие в Android Studio

1. Откройте папку **True Path** как проект.
2. Выберите JDK 17+; подходит встроенный JBR Android Studio.
3. Установите Android SDK Platform 36 и выполните Gradle Sync.

Проект: Kotlin 2.1.21, Jetpack Compose, Material 3, Java 17, Android 8.0+ (`minSdk 26`), `compileSdk / targetSdk 36`, AGP 8.13.2, Gradle 8.13.

`local.properties` создаётся Android Studio для локального пути SDK и не хранится в Git.

## Проверки без APK

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:compileDebugKotlin :app:testDebugUnitTest :app:lintDebug
```

Эти задачи проверяют компиляцию, доменную логику и Android Lint. Они не запускают сборку APK. Не используйте задачи `assemble`, `package` и `bundle`, если создание установочных артефактов не требуется.

Интерфейс на устройстве пока не проверен: APK по условию задачи не создаётся. Для визуальной проверки добавлен отдельный режим рендеринга Compose на компьютере (Paparazzi), без эмулятора и установочного файла:

```powershell
.\gradlew.bat :app:recordPaparazziDebug -Pscreenshots
.\gradlew.bat :app:verifyPaparazziDebug -Pscreenshots
```

Эталонные снимки находятся в `app/src/test/snapshots/images/`, тесты — в `app/src/screenshot/java/`. Обычный запуск unit-тестов не включает визуальные тесты; флаг `screenshots` добавляет их отдельно. Учебные фотографии при рендеринге берутся из локальных ресурсов, без сетевых запросов. Снимки на компьютере не заменяют проверку жестов, системного выбора файлов и внешнего видеоплеера на устройстве.

## Состояние исследований

Полученные узлы, связи и идентификаторы обработанных событий сохраняются во внутреннем каталоге приложения. Повторные события не создают дубликаты. Связи ждут появления обоих узлов. При перезапуске процесса незавершённый пример отмечается прерванным; его можно продолжить. Ошибка и окончание потока без итогового события не считаются успешной проверкой.

Граф рисуется нативно в Compose Canvas. Его элементы, цитаты и пояснения доступны в выдвижном меню справа. Основной экран оставлен под граф, исходный материал и финальный вывод. Положение камеры сохраняется во время потока; кнопка обзора возвращает весь путь, а меню позволяет сфокусировать выбранный узел. Цвет сопровождается текстовым статусом. История не синхронизируется между устройствами; резервное копирование данных приложения отключено.

## Что подключить далее

Заменить `DemoResearchSource` реализацией `ResearchSource`, использующей внешние API напрямую из приложения. Поставщик должен отдавать структурированные промежуточные данные, а не только финальный текст. Подробности — в [контракте](docs/API_CONTRACT.md).

## Журнал и медиа

[Журнал разработки](docs/DEVELOPMENT_LOG.md) фиксирует этапы, решения, проверки и ограничения для последующего описания пайплайна. Подробные сообщения коммитов дополняют его.

Новость состоит из упорядоченных `ArticleBlock`: абзац, фото, видео, ссылка. Это сохраняет расположение медиа внутри текста. Для фотографии доступны подпись, авторство, загрузка по HTTPS, состояние ошибки и полноэкранный просмотр с масштабированием. Ссылки внутри абзацев кликабельны. Встроенного видеоплеера пока нет.

Происхождение учебных иллюстраций описано в [ASSET_CREDITS.md](docs/ASSET_CREDITS.md).
